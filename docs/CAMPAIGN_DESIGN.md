# 单机狼人杀「闯关 + 自由对局」实施依据

状态：草案 v2（已按评审修订，作为实施依据）。本文件只规划，不含代码。
模型 + 猜想模式接通单列为后续项目，不纳入本版 v1 里程碑。

---

## 1. 定位与原则

本机运行的单人狼人杀：玩家对 NPC，Web 与终端共用 `GameSession`、存档与进度。「单机」不等于离线——NPC 决策、角色教学、失败复盘全程由模型驱动，不静默降级。

**模型与确定性代码的边界（必须遵守）：**

- 确定性代码负责：规则、技能合法性（如女巫是否能同时用药）、胜负判定、角色与板子校验、结算计数。
- 模型负责：讲解、决策、复盘。
- 教学生成失败：显示「暂不可用，请重试」，**不得**用占位文本伪装成模型教学。
- 复盘失败：不影响已保存的成绩，允许稍后重试。
- 胜负与成绩**先提交、后复盘**：复盘绝不嵌入胜负结算的原子提交。

## 2. 三个主入口

| 入口 | 说明 | 现状 |
|---|---|---|
| 开始闯关 | 从平民起，逐关解锁角色 | 新增 |
| 自由对局 | 角色/板子/人格/猜想选项 | 现有，加 UI 收口 |
| 继续游戏 | 恢复未结束对局或闯关进度 | 复用 `restore_game` / `--resume` |

首次进入：完成模型连接 + 简短教学，之后读本地设置、不再重复配置。对话入口提供同样三选一，不要求开网页。本地设置文件 gitignore、不进库、不进发布包；**配置快照不保存密钥**（沿用 checkpoint 已排除 `api_key` 的做法）。

## 3. 闯关模式

### 3.1 胜利判定（已修订）

引擎胜负为阵营级：`winner ∈ {"god", "wolf", "draw"}`。

- `"god"`：好人阵营（神 + 民）胜（狼全灭）。
- `"wolf"`：狼阵营胜（屠边：神全灭或民全灭）。
- `"draw"`：平局（仅 round_limit 板出现）。

玩家阵营映射：**狼阵营角色（`WOLF_ROLES`）对应 `"wolf"`，其余可玩角色一律对应 `"god"`**（`civilian` 阵营属于好人侧，没有 `winner="civilian"`，不能直接比较）。

- 通关 = `(玩家阵营 == "wolf" and winner == "wolf") or (玩家阵营 != "wolf" and winner == "god")`。
- 不要求本人存活。
- **平局：计一次尝试、不通关、单独记录，不混入负局。**

### 3.2 解锁与计数

- 当前角色赢一局 → 解锁下一关；输局可无限重试。
- 每关记录：开始尝试数、胜负次数；全局累计总局数、累计轮数（昼夜数）、实际游玩时长。
- **v1 即保留多次通关记录与最佳总局数**；多档案管理后做。
- **耗时口径（已修订）**：昼夜数属于「对局轮数」，不是时间，二者分开记录：
  - 累计轮数 = 已完成对局的昼夜数之和。
  - 实际游玩时长 = 玩家真实游玩的墙钟时间，**暂停 / 中断不计入**。
- 最佳成绩仍以总局数为主，轮数与时长仅作参考。

### 3.3 尝试生命周期与可恢复故障（已修订）

`_game_task` 当前的 `finally` 会把异常退出也标成 `finished=True`，因此「模型故障可续玩」**不是现成能力**，必须显式拆分终态。

**尝试开始（已补充）**：档案已登记、但对局检查点尚未生成时，不能直接计为一次有效尝试。引入 `preparing` 状态——仅当对局初始化存档成功后才计入尝试数；启动时清理或重试未完成的准备。

| 终态 | `finished` | 闯关结算 | 说明 |
|---|---|---|---|
| preparing（准备中） | false | 不计数 | 档案已登记、检查点未生成 |
| 正常终局 | true | 结算胜负 | 胜负已定 |
| 主动放弃 | true | 计一次未胜 | 玩家明确放弃 |
| 可恢复故障 | **false** | 不计负、不结算 | 模型故障，修好续玩 |
| 正常暂停 | false | 不结算 | 已检查点、未结束 |

异常退出（模型故障）既不是输局，也不触发通关结算。这需要调整 `_game_task` 的终态判定，与正常终局/主动放弃分开。

## 5. 存档设计

两类文件分开，**不共享原子提交**。

- **对局存档**：复用现有 checkpoint（原子写、校验、0700/0600、gitignore）。
- **闯关档案**：新本地 JSON 存储（`SCHEMA_VERSION` + 原子写 + 校验），含已解锁关卡、每关成绩、当前对局关联、通关记录、模型配置 + 规则版本快照。

### 5.1 结算去重与崩溃补记（已修订）

不能靠「对局存档 + 闯关档案」各自原子写来实现共同原子提交，也不建议挂在 `_game_task.finally`。改为：

1. 对局存档**先持久化不可变的终局结果**（`winner` / `end_reason` / `finished`）。
2. 闯关档案以 **`game_id` 作为结算去重键**。
3. **启动或恢复时补处理**「对局已结束、档案尚未更新」的结果：发现终局检查点但档案无该 `game_id` 结算记录，就补记一次，幂等。
4. 尝试开始时的「档案 ↔ 对局」关联同样按此处理：档案先记 `game_id + preparing`，初始化存档成功后才置为 `in_progress` 并计入尝试数；启动时清理或重试仍处 `preparing` 的未完成准备，再按检查点状态对账补记。

这样无论在哪一步崩溃，都能补记且不重复。同一 `game_id` 至多结算一次；恢复多次不重复结算。

### 5.2 本地与安全

- 所有存档与设置仅本地，gitignore 且纳入 `check_release.py` 排除。
- **个人本地游戏不需要防作弊系统**：只保证正常操作不重复计数、不丢进度，不防御玩家自行修改存档。

---

## 6. 自由对局

保留角色/随机、板子、猜想开关、固定/随机人格、可保存退出继续。

- **现状约束**：模型玩家 + 猜想模式尚未接通（构造时即拒绝）。界面必须在选择前明示限制，不能选完报错；接通前该开关对模型模式置灰。
- 主线配置固定板子与人格生成规则，记录实际人格、模型、规则版本；换模型续玩允许，但标记配置变化。

---

## 7. 教学与复盘（全模型，带降级边界）

- 每关首次进入：模型生成角色教学（技能、行动时机、阵营胜利条件）。失败显示「暂不可用，请重试」。
- 失败后：模型生成短复盘，指出一两个关键决策（喂入 `decision_log` + `vote_log` + `public_record` 的翻牌事实）。
- 复盘在终局后**独立一步**执行；失败给兜底提示、允许稍后重试，且不影响已保存成绩。
- 活局中只解释规则（沿用 `answer_rule_question`），主持人不提供全知策略提示。

---

## 8. 实验挑战（与主线分开）

主线 = 普通模式、固定板子规则，保证「多少局通关」有一致比较基础。神女巫、极端人格、猜想模式归实验挑战，独立入口、独立成绩。模型 + 猜想模式接通单列为后续项目，**不进入 v1 里程碑**。

---

## 9. 范围

**v1 交付**：三入口 + 角色闯关 + 自动续存 + 通关局数（含多次通关记录与最佳总局数）+ 教学/短复盘 + 本地设置。

**明确不做（v1）**：装备、货币、天赋树；全球排行榜/公平竞技宣称；多档案管理（后做）；实验挑战可玩化（仅留入口说明）；模型 + 猜想接通（后续项目）；防作弊系统。

---

## 10. 验收标准

1. 同一局恢复多次，闯关只结算一次（核心）。
2. 进程中断 → 恢复，续玩位置与胜负判定正确。
3. 模型故障暂停不计负、不新增尝试、不触发结算；明确放弃计一次未胜。
4. 平局计尝试、单独记录、不混入负局。
5. 已通关角色练习单独统计，不影响本次闯关成绩。
6. 所有存档与设置本地化，gitignore 且 `check_release.py` 排除；配置快照不含密钥。
7. 自由对局的猜想限制在选择前明示。
8. 完整闯关、放弃、故障续玩、重复恢复、多次通关成绩全部覆盖。
9. 尝试开始失败（档案登记、检查点未生成）不计入尝试数，启动时清理或重试未完成准备。
10. 累计轮数与实际游玩时长分别记录，暂停/中断不计入时长。

---

## 11. 实施顺序

1. 核对角色、板子与胜负映射，锁定主线关卡表。
2. 定义尝试生命周期、计数口径与可恢复故障（拆分 `_game_task` 终态）。
3. 实现闯关档案、对局关联、幂等结算与崩溃补记（含 `preparing` 清理/重试）。
4. 接入 Web/终端三入口与本地设置；配置快照不保存密钥。
5. 加角色教学与独立的终局短复盘。
6. 验收完整闯关、放弃、故障续玩、重复恢复与多次通关成绩。
